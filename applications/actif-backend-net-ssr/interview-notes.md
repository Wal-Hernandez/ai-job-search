## STAR Stories

### Story 1: Legacy .NET to Node.js + AWS Migration (La Nacion)

**S:** The newsletter system ran on .NET 2.2 with AWS Lambdas and complex dependencies, hard to maintain.
**T:** Lead the backend migration to Node.js, define the new architecture, ensure no disruption.
**A:** Mapped existing Lambdas and data flow, proposed Node.js replacement with AWS services, designed APIs, coordinated with frontend team for incremental integration.
**R:** Working Node.js backend replaced legacy stack, improved maintainability, gave team clear path forward.

### Story 2: AI Document Analysis (Eppical)

**S:** Insurance client needed automated document processing from scanned PDFs and images.
**T:** Integrate AI-based OCR and document analysis into the product.
**A:** Researched and integrated OpenAI APIs for image analysis and PDF text extraction, wired them into C#/.NET and Node.js backend, built Angular frontend for review/validation.
**R:** Client processed documents significantly faster. Feature became part of core product.

### Story 3: Architecture Refactoring (Eppical)

**S:** The main application was a monolithic project making deployment and feature development slow.
**T:** Improve scalability and code reuse by separating concerns.
**A:** Proposed and led separation into frontend, backend, and database layers. Refactored existing code for the new structure.
**R:** Improved scalability, enabled independent deployment of layers, improved code reuse across the application.

## Behavioral Questions

### "Why this role?"

"This role aligns with where I'm taking my career: deeper backend ownership, microservices on AWS, and working on SaaS products that incorporate AI. I have the C#/.NET and AWS experience you need, and the AI integration work I did at Eppical gives me a head start on the kind of products you build."

### "Where do you see yourself in 3-5 years?"

"I want to become a backend architect who combines deep systems design with AI and data engineering. This role would help me grow in microservices, event-driven architectures and cloud-native patterns while contributing to products that use AI."

### "How do you handle ambiguity in requirements?"

"I ask direct questions and document the answers. At La Nacion, the newsletter migration started as a vague brief. I mapped the existing system, clarified what success looked like, proposed phases, and got alignment before writing code. I prefer surfacing uncertainty early rather than building the wrong thing."

### "Tell me about a time you disagreed with a technical decision."

"I focus on evidence. If I think a different approach would work better, I bring data or a prototype. At La Nacion, when we discussed how to structure the Paywall monorepo's backend services, I proposed a modular design and walked the team through how it would reduce coupling compared to the alternative. If the team goes another direction after discussion, I commit fully to the decision."

### "How do you stay current with technology?"

"I read technical documentation, follow AWS and .NET release notes, and actively learn through side study. I'm currently completing a degree in Information Security and learning Docker and IaC tools because I want deeper cloud engineering skills. I also learn through peer code reviews and technical discussions at work."
